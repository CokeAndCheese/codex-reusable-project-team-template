# {{PROJECT_NAME}} — 决策日志

> 仅记录用户批准、撤销或替换的长期产品、架构、人员、风险、工作流和发布决策。按时间追加，不覆盖历史。

## 记录规则

- 未经用户批准的方案写入产品建议或 `ORG_CHART.md` 的“提议中”，不能伪装成有效决策。
- 同一决策发生变化时新增一条记录，并明确替换关系；不要改写旧记录。
- 日常任务拆解、普通 bug、局部实现选择不进入本日志。
- 每条记录应能在脱离历史 Chat 后独立解释其背景、结论和边界。

## 建议在项目启动时向用户确认的治理决策

- 任命产品经理与项目总控。
- 用户只处理哪些决策问题。
- 人员 Chat 命名和人事变更汇报规则。
- 单工作区、单写入队列、轻量 Git 和备份方式。
- 是否连接远端、是否允许部署或外部发布。
- 第一个产品里程碑及关闭条件。

这些项目只有在用户明确确认后，才能作为有效决策逐条写入下面的日志。

## {{DATE}} — {{DECISION_TITLE}}

- **状态**：有效 / 已替换 / 已撤销。
- **背景**：为什么现在需要决定。
- **决策**：用户明确批准、撤销或替换的内容。
- **边界**：该决策没有授权什么。
- **影响**：范围、架构、人员、成本、风险、交付或发布影响。
- **证据/记录**：相关文档、检查点或验收结果。
- **替换关系**：如适用，指出替换或撤销的旧决策。
