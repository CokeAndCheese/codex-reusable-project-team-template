# {{PROJECT_NAME}} — 单工作区研发与里程碑备份流程

> 生效日期：{{EFFECTIVE_DATE}}
> 模式：单工作区＋本地轻量 Git＋里程碑手动备份
> 流程所有者：`{{PROJECT_NAME}}产品经理-项目总控`

## 1. 唯一工作区

所有研发写入统一使用：

```text
{{WORKSPACE_PATH}}
```

默认不创建额外 worktree，不把 PR 当作本地研发必经流程。同一时刻只允许一个本地任务分支和一个实施角色写入。

## 2. 派发顺序

1. 产品经理确认工作已获批准，定义目标、范围、非目标和验收标准。
2. 先匹配项目内现有长期角色 Chat，并记录负责人。
3. 没有合适角色、需要一次性独立审查或角色受限时，才使用临时子 Agent；派发前记录原因、映射职责和同步对象。
4. 分配写入权、文件或系统边界 owner，并记录开始时工作区状态。
5. 实现者完成后交回变更文件、验证证据、未完成项和工作区状态。
6. 产品经理明确释放或转交写入权后，下一角色才能写入。

## 3. 单一写入队列

- 任一时刻只有一个实现任务可以修改代码或文档。
- 技术负责人、QA 和其他角色可以并行只读研究与评审。
- 紧急缺陷先暂停当前写入者，再把写入权交给明确负责人。
- 不允许通过多个 Chat 同时改同一工作区来换取表面并行速度。

## 4. 轻量 Git

Git 用于：

1. 审查精确差异。
2. 保存可恢复的本地检查点。
3. 定位和恢复单文件或单次变更。
4. 保存已验收里程碑历史。

默认规则：

- 任务分支前缀：`{{TASK_BRANCH_PREFIX}}`。
- 本地主分支：`{{DEFAULT_BRANCH}}`。
- 使用精确路径暂存，禁止 `git add .`。
- 不 stash、reset、clean、覆盖或提交用户拥有的改动。
- 检查点必须经过相关验证和产品经理 diff 核对。
- 默认本地模式：未经额外授权不 fetch、pull、push、创建 PR、检查远端、发布或部署。

## 5. 工作包流程

```text
用户批准目标
→ 产品经理拆解工作包
→ 登记长期角色 owner
→ 分配唯一写入权
→ 实现与专项测试
→ 交回写入权
→ 技术负责人只读复核
→ QA 独立验收
→ 产品经理产品验收
→ 用户只接收里程碑结论或真实决策
```

## 6. 普通检查点

高风险、跨日或可独立回滚的切片可以创建本地 checkpoint：

```text
完成可验证切片
→ 跑相关门禁
→ 产品经理审查精确 diff
→ 精确暂存授权文件
→ 创建本地 checkpoint commit
```

普通检查点不等于用户已验收里程碑，也不等于已经发布。

## 7. 里程碑关闭

```text
所有工作包完成
→ 技术负责人完成架构/接口复核
→ QA 独立验收
→ 产品经理核对范围、证据与遗留风险
→ 用户确认里程碑
→ 创建本地里程碑 commit
→ 用户执行外部手动备份
→ 用户确认备份完成
→ 更新 PRODUCT_CONTEXT / DECISION_LOG
→ 开启下一高风险里程碑
```

## 8. 手动备份

备份应包含：

- 源码、文档、脚本和 `.git` 元数据。
- Git 未跟踪但产品运行必需的资产。
- 权威契约、数据 schema、验收报告、决策日志和组织架构。

通常可排除：依赖目录、缓存、日志和可重新构建的产物。真实凭据不进入普通项目备份；如必须备份，使用独立加密存储。

建议命名：

```text
{{PROJECT_SLUG}}_{{MILESTONE_ID}}_YYYY-MM-DD_HHMM
```

## 9. 恢复原则

- 单文件或局部错误：优先使用 Git diff/history 精确恢复。
- 整个工作目录或 Git 元数据损坏：使用最近的外部里程碑备份。
- 资产损坏：从资产备份恢复并重新执行契约校验。
- 凭据丢失或安全性不明：从加密存储恢复或先轮换，不从普通备份复制。
