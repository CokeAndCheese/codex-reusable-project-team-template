## 1. 唯一工作区

所有研发写入统一使用：

```text
{{WORKSPACE_PATH}}
```

默认不创建额外 worktree，不把 PR 当作本地研发必经流程。同一时刻只允许一个本地任务分支和一个实施角色写入。

## 2. 派发顺序

严格使用 `$project-team-orchestrator` 的统一派单算法，并保持以下顺序：

0. 先验证模型策略 schema：完整 v2 才能真实派单；v1、无效 v2 或未知版本按 Skill 停止码处理。显式速度变更还要求 `service_tier_policy`。
1. 确认工作已获批准，定义目标、范围、非目标、验收和外部权限。
2. 交叉核对任务列表、生效组织与 Registry：全项目只有一个总控标题/ID，每个长期职责只有一个准确任务 ID。
3. 优先匹配唯一长期角色。只有符合例外条件时才选临时 Agent，并先记录原因、映射职责、一次性范围、同步对象和关闭方式。
4. 临时工作默认用 fresh-context 轻量 Agent；独立 QA 不从总控/实现者 fork。同职责已有活动临时项时复用，替换超过一次时停止审查。
5. 补齐工作包、角色 owner、文件/系统边界、依赖、验证和当前写入状态。
6. 若涉及发布批准、重大风险接受、不可逆决定或外部/破坏性动作，先核对明确用户授权证据；缺失即停止并升级用户。
7. 对团队内部最终裁决或建议，核对目标 Profile 的总开关与该裁决授权列表；未通过即停止并重新分工。
8. 计算任务类别、Profile 默认值或单次 override 形成的候选 tier。
9. 汇总阶段、风险 trigger、用户保留决定、内部裁决、Profile 和工作包的最低 tier。
10. 选择不低于有效下限且不超过 Profile 最大值的 tier。
11. 独立选择 speed：默认 Standard；Fast 只在项目授权边界内。不得从 reasoning 推导速度。
12. 分别核对目标 Host/工具支持的精确 model/reasoning 与 service tier；无法设置速度时返回手动动作或未验证状态。
13. 为写任务分配唯一写入权和明确文件/系统边界，并记录开始时工作区状态；只读任务不发写入权。
14. 把完整工作包与工具支持的显式 model/reasoning/speed 设置一起派发；不单独发送空的换模或换速轮次。
15. 实现者交回变更与证据并请求归还写入权；产品经理确认后再组织复核、QA、验收或下一次派单。临时执行单元在回流后关闭并按授权归档。

## 3. 单一写入队列

- 任一时刻只有一个实现任务可以修改代码或文档。
- 技术负责人、QA 和其他角色可以并行只读研究与评审。
- 紧急缺陷先暂停当前写入者，再把写入权交给明确负责人。
- 不允许通过多个 Chat 同时改同一工作区来换取表面并行速度。
- 模型升级或降级不改变当前写入者、文件所有权或单一写入队列；所有权切换仍需独立交接。

## 4. 轻量 Git

Git 用于：

1. 审查精确差异。
2. 保存可恢复的本地检查点。
3. 定位和恢复单文件或单次变更。
4. 保存已验收里程碑历史。

默认规则：

- 任务分支前缀：`{{TASK_BRANCH_PREFIX}}`。
- 本地主分支：`{{DEFAULT_BRANCH}}`。
- 使用精确路径暂存，禁止 `git add .`。
- 不 stash、reset、clean、覆盖或提交用户拥有的改动。
- 检查点必须经过相关验证和产品经理 diff 核对。
- 默认本地模式：未经额外授权不 fetch、pull、push、创建 PR、检查远端、发布或部署。

## 5. 工作包流程

```text
用户批准目标
→ 产品经理拆解工作包
→ 核对唯一总控/长期角色任务并登记 owner
→ 核对 fresh-context 临时例外、数量、替换和关闭计划
→ 核对用户保留决定与内部裁决权限
→ 分别计算并记录 model/reasoning 路由与 Standard/Fast speed
→ 分配唯一写入权
→ 实现与专项测试
→ 交回写入权
→ 技术负责人只读复核
→ QA 独立验收
→ 产品经理产品验收
→ 用户只接收里程碑结论或真实决策
```

## 6. 普通检查点

高风险、跨日或可独立回滚的切片可以创建本地 checkpoint：

```text
完成可验证切片
→ 跑相关门禁
→ 产品经理审查精确 diff
→ 精确暂存授权文件
→ 创建本地 checkpoint commit
```

普通检查点不等于用户已验收里程碑，也不等于已经发布。

## 7. 里程碑关闭

```text
所有工作包完成
→ 技术负责人完成架构/接口复核
→ QA 独立验收
→ 产品经理核对范围、证据与遗留风险
→ 用户确认里程碑
→ 创建本地里程碑 commit
→ 用户执行外部手动备份
→ 用户确认备份完成
→ 更新 PRODUCT_CONTEXT / DECISION_LOG
→ 开启下一高风险里程碑
```

## 8. 手动备份

备份应包含：

- 源码、文档、脚本和 `.git` 元数据。
- Git 未跟踪但产品运行必需的资产。
- 权威契约、数据 schema、验收报告、决策日志和组织架构。

通常可排除：依赖目录、缓存、日志和可重新构建的产物。真实凭据不进入普通项目备份；如必须备份，使用独立加密存储。

建议命名：

```text
{{PROJECT_SLUG}}_{{MILESTONE_ID}}_YYYY-MM-DD_HHMM
```

## 9. 恢复原则

- 单文件或局部错误：优先使用 Git diff/history 精确恢复。
- 整个工作目录或 Git 元数据损坏：使用最近的外部里程碑备份。
- 资产损坏：从资产备份恢复并重新执行契约校验。
- 凭据丢失或安全性不明：从加密存储恢复或先轮换，不从普通备份复制。
